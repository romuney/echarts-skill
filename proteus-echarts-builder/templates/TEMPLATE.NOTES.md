## §2 ПРОЧИТАНО

Диапазоны обязаны покрыть 1..M без дыр — это доказательство полноты чтения.

M берётся ТОЛЬКО из вывода `wc -l <name>.html`. Не с глаз, не «примерно»,
не по последней прочитанной строке. `validate.py` сверяет это число с файлом
и роняет сдачу при расхождении: «покрыто M из M» с выдуманным M ничего не доказывает.

## §3 ПОЛЯ: ЧТО ЖДЁТ МАКЕТ ↔ ЧТО ДАЁТ SQL

собственном `<script>`: обращения вида `row.<поле>`, `data.filter(...)`, ключи
объектов в моке. Это фактический контракт данных, и он сильнее твоих догадок.

| Поле, которое ждёт макет | Где в HTML | Есть в SQL? | Колонка SQL |
|---|---|---|---|

Каждое «нет» — блокирующее расхождение. Закрывается вопросом пользователю (§4),
а не молчаливой перекройкой виджета под то, что есть в SQL.

Отдельно сверь ФОРМУ данных: макет ждёт массив строк или одну агрегатную строку?
Если макет фильтрует `data` по какому-то ключу, а SQL отдаёт одну строку —
это расхождение того же класса.
