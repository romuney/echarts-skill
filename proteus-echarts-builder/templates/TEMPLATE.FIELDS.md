# FIELDS — поля для «Измерений» Proteus

Поля из SQL не попадают в `data` автоматически. Каждое поле ниже нужно вручную
добавить в панель «Измерения» с точным именем.

Правило синхрона: **имя в SQL == имя в «Измерениях» == ключ в `CFG.fields`**.
Любое расхождение — поле не дойдёт до графика (RETRO 17).

Типы в Proteus: `f(x)` — вычисляемое, `#` — число, `abc` — строка.

## Поля графика

Заполни таблицу ФАКТИЧЕСКИМИ полями из SQL пользователя. Не копируй примеры бездумно.

| Поле (точное имя) | Тип | Назначение | Обязательно | Добавлено в «Измерения» |
|---|---|---|---|---|
| | | Разрез / категория | | нет |
| | | Период (укажи тип: DATE / DATETIME / строка) | | нет |
| | | Метрика | | нет |

Для поля-даты ОБЯЗАТЕЛЬНО укажи тип колонки: `DATETIME` часто приходит в `data`
epoch-числом, а не строкой, которая видна в UI-таблице.

Последняя колонка — не украшение: пока там «нет», поле физически отсутствует в `data`,
и в JS будет `undefined`.

## Что считается в JS, а что в SQL

По умолчанию все производные величины считает JS в `buildModel()` — база не
нагружается (SKILL.md, правило 2). Сюда пиши ТОЛЬКО те расчёты, которые по явному
согласованию с пользователем остались в SQL, и почему.

| Расчёт | Где считается | Почему | Кто согласовал |
|---|---|---|---|
| | JS / SQL | | |

## Статические значения (не из SQL)

Значения из макета, которые по согласованию с пользователем остаются справочником в коде:

| Значение | Где в макете | Кто подтвердил |
|---|---|---|
| | | |

Пусто — значит все данные пришли из SQL. Заполнять строку можно ТОЛЬКО после явного
ответа пользователя. Самовольно захардкоженные значения = FAIL по SELF_CHECK M4.

## Настроить РУКАМИ в Proteus (skill этого не делает)

Это задачи ПОЛЬЗОВАТЕЛЯ, а не агента. Агент оставляет их пустыми `[ ]` и заполняет
только текст в скобках. Ставить `[x]` за пользователя ЗАПРЕЩЕНО: галочка означает
«в Proteus реально настроено», и ложная отметка прячет причину пустого виджета.

- [ ] Тип визуализации: ECHARTS.
- [ ] Измерения: все поля из таблицы выше, точными именами.
- [ ] Сортировка: [УКАЖИ поле/функцию]. Дефолт для временных рядов: `f(x) MAX(<поле периода>)`.
- [ ] Упорядочивание: [УКАЖИ колонку или оставь пустым].
- [ ] Сортировка по убыванию: [вкл/выкл].
- [ ] Лимит строк: [значение].
- [ ] Серверная пагинация: [вкл/выкл] — может перебить `ORDER BY` из SQL.
- [ ] Фильтры: [список].

Если JS опирается на порядок строк, без верной сортировки в UI график построится криво.
В самом JS всё равно делай явный `sort` по распарсенному периоду.
