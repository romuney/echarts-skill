# PATTERNS — RETRO каркаса и рецепты

Реестр реальных падений на каркасе, overlay и тултипе. Каждое — баг из практики.
Читай ПЕРЕД кодом.

Правило реестра: **номер RETRO уникален и никогда не переиспользуется.** Новый баг
получает следующий свободный номер. На номера ссылаются `SELF_CHECK.md` и `validate.py`.
RETRO про сложные таблицы (поиск, сортировка, пагинация, экспорт) — в `TABLES.md`,
номера 27–40.

## Рецепт: перенос CSS макета

Кладётся в `buildCSS()` массивом строк с `join('')`. Первый элемент `'<style>'`,
последний `'</style>'`. Переменная `P = '.' + CFG.ns` подставляется в каждый селектор.
Значения берутся из `CFG.colors/fonts/spacing`, а не пишутся числами в строке.
Цвета удобно держать как `[R,G,B,A]` и гонять через `cssColor()`.

Динамические значения (ширина бара, цвет ячейки по шкале) остаются инлайн
в `style="..."` — их нельзя выразить статичным правилом.

## Рецепт: перерисовка и интерактив

`render()` полностью пересобирает `overlay.innerHTML`. Обработчики делегированы от
overlay и навешены ОДИН РАЗ снаружи `render()` — узел overlay при `innerHTML` не
пересоздаётся, поэтому слушатели переживают перерисовку (RETRO 9).

Клик по переключалке: меняет `state`, вызывает `render()`. Никакого ручного патча
отдельных узлов параллельно с полным рендером — один источник правды.

Для частых событий (`mousemove` по ячейкам) не вызывай `render()`: меняй только
стиль/текст тултипа и классы подсветки.

## Рецепт: тултип, который реально работает

Четыре условия, все обязательные:

1. **Живёт в `body`, создаётся один раз.** Узел создаётся в `mount()` ДО первого
   `render()` и кэшируется. В `buildHTML()` его НЕТ — иначе `innerHTML` убьёт узел.
2. **`position:fixed` и свой `font-family`.** Тултип вне `.<ns>-root`, поэтому не
   наследует ни шрифт, ни цвет. Координаты — от `getBoundingClientRect()` цели,
   КАК ЕСТЬ, без вычитания rect корня; клампинг по `window.innerWidth/innerHeight`.
   Мало места справа — отрисуй слева от цели, мало снизу — сверху (RETRO 26).
3. **hover не вызывает полный `render()`.** Для hover — лёгкий `renderTip()`, который
   меняет только содержимое и позицию тултипа. Полный `render()` — только на клик.
4. **Видимость — только через `showTip()/hideTip()` шаблона.** Тултип спрятан двумя
   свойствами (`display:none` + `opacity:0`), и показ обязан снять оба. Свой
   `tip.style.opacity` / `tip.style.display` не писать НИКОГДА: снятое наполовину
   скрытие даёт полностью невидимый тултип при верных событиях, координатах
   и тексте — самый дорогой в отладке вид поломки (RETRO 44).

Пункты 2 и 4 уже реализованы в служебных `showTip()/hideTip()` — они не
`[ЗАПОЛНИ]`, их не трогают. Твоё — только содержимое и якорь:

```js
function renderTip() {
  if (!state.tip) { hideTip(); return; }
  var html = '<div class="' + CFG.ns + '-tip-title">' + esc(title) + '</div>';
  showTip(html, state.tip.rect);
}
```

Делегированный `mouseout` срабатывает и при переходе курсора на ДОЧЕРНИЙ узел той же
ячейки — тултип начинает мигать. Проверяй `e.relatedTarget`: если он всё ещё внутри
той же цели (`target.contains(e.relatedTarget)`), тултип не гасим.

## Рецепт: единый шрифт

Стек задаётся ОДИН раз в `CFG.fonts.family` и подставляется в ДВА места:
в `.<ns>-root` и в правило `.<ns>-tip`. Внутри корня добавь `font-family:inherit`
для `*`: `button` и `input` НЕ наследуют шрифт по умолчанию и берут системный.
Никаких локальных `font-family` в отдельных правилах быть не должно.

## Рецепт: скролл и габариты

Overlay всегда `position:absolute` с `width/height:100%` и `overflow:auto`.
Внутри разделяй фиксированную шапку и скроллируемое тело через flex-колонку,
иначе на маленьком виджете управление уезжает за пределы.

## Рецепт: большие объёмы (JS-first)

Считает JS, база не нагружается (SKILL.md, правило 2). Лестница по объёму:

1. **до ~100 строк** — обычный полный `render()`, ничего оптимизировать не надо;
2. **100–1000 строк** — пагинация; поиск и сортировка идут поверх JS-модели,
   SQL не трогаем;
3. **1000+ строк** — в DOM живёт ТОЛЬКО текущая страница, полная модель — в JS.
   Скрытие лишних строк через `display:none` проблему НЕ решает: узлы всё равно
   созданы. Сначала срез страницы, потом сборка HTML;
4. **строки не влезают в лимит Proteus** — и только тогда предложи пользователю
   схлопнуть гранулярность в SQL. Спроси согласие и предупреди, что новую колонку
   придётся вручную добавить в «Измерения» (SKILL.md, КОНТРАКТ п. 4).

Упаковка выборки в компактную строку на стороне SQL с распаковкой в `buildModel()` —
крайняя мера: только с явного согласия, способ и его точность фиксируются в `FIELDS.md`.
Отдельная колонка с честным итогом до лимита нужна, чтобы виджет показал
«Показано X из Y» — она тоже требует согласия и ручного добавления в «Измерения».

Пороги — практические defaults, а не строгие бенчмарки.

Частые события (поиск) — через debounce. Полный `render()` на `mousemove` не делать
никогда. Слушатели — делегированием от overlay.

## Рецепт: «не работает» — сначала мерить, потом править

Самая дорогая ошибка отладки — чинить наугад. Перебор правдоподобных гипотез
(`mouseover` → `mouseenter`, overlay → `document`, `absolute` → `fixed`) выглядит
как работа, но каждая итерация переписывает КОРРЕКТНЫЙ код, жжёт контекст и
уводит от причины. Реальный случай: девять итераций и два часа на правку,
которая занимает одну строку, — и все девять трогали то, что не было сломано
(RETRO 44).

**Правило: одна слепая догадка — максимум. Не помогла — переходи на измерение.**

Отрисовка — цепочка. Сломано ровно одно звено, и его надо назвать до правки:

| # | Звено | Чем меряется |
|---|---|---|
| 1 | данные пришли | `rawData.length`, `MODEL` — есть ли строки и та ли форма |
| 2 | разметка построена | `overlay.innerHTML.length`, узел `.<ns>-root` в Elements |
| 3 | событие дошло | слушатель есть на overlay, `e.target` — тот узел |
| 4 | обработчик отработал | состояние изменилось: `state.tip` не `null` |
| 5 | узел существует | `document.querySelector('body > .<ns>-tip')` не `null` |
| 6 | узел ВИДИМ | `getComputedStyle(node)` — `display`, `visibility`, **`opacity`** |
| 7 | узел в кадре | `getBoundingClientRect()` — размер не нулевой, координаты во вьюпорте |

Звенья 6 и 7 проверяются последними, а ломаются чаще всего — и именно они не
дают ни ошибки, ни пустого экрана. Дополнительно: `getComputedStyle` РЕБЁНКА
врёт про прозрачность — у потомка внутри `opacity:0` он вернёт `1`. Прозрачность
считается перемножением по всем предкам.

Быстрее всего цепочку проходит `smoke.mjs`: он гоняет её целиком, включая
пиксельную проверку (звено 6+7 разом), и печатает, какое звено порвалось.
Гипотеза «не всплывают события» проверяется одним запуском, а не правкой кода.

## Рецепт: работа с большим макетом

Захлебнуться контекстом на макете в 2000 строк — такое же реальное падение, как
синтаксическая ошибка, и выглядит хуже: половина элементов молча теряется.

Симптом: к БЛОКУ 5 агент уже не помнит, что было в шапке макета, и «додумывает»
разметку. Причина: HTML и реестр держались в контексте, а не на диске.

Лечение — правила 3–6 SKILL.md: `<name>.NOTES.md` создаётся ДО чтения макета,
диапазоны по ≤300 строк, после каждого диапазона запись в §1/§2, после каждого блока
JS — чекпоинт в §5. Перед сдачей §2 обязана покрывать 1..M без дыр, а каждая строка
§1 — иметь статус DONE со ссылкой `<name>.chart.js:строка`.
