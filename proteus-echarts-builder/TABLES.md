# TABLES — сложные интерактивные таблицы

Читай ЭТОТ файл, только если в макете есть таблица с чем-то из списка: поиск,
фильтры, сортировка, пагинация, копирование/экспорт, перестановка или выбор колонок,
сворачивание групп, sticky-колонки. Обычный график или снимок — не читай.

Базовый каркас работает и без этого файла. Здесь — архитектура, без которой соседние
функции начинают ломать друг друга после каждой правки.

# 1. PIPELINE: DOM — ЭТО ТОЛЬКО ТЕКУЩАЯ СТРАНИЦА

```
rawData → MODEL → filter/search → sort → PAGE_ROWS → DOM
                                     ↘
                                      export/copy: ВСЕ отфильтрованные строки
```

Единственное правило, из которого следует почти весь этот файл:
**пагинация — это способ ограничить DOM, и только.** Она не меняет семантику поиска,
сортировки и копирования.

Отсюда:

- Поиск и фильтрация идут по ПОЛНОЙ модели, а не по отрендеренным строкам.
- Сортировка идёт после фильтрации и до нарезки страницы.
- Пагинация применяется ПОСЛЕДНЕЙ.
- Экспорт ответвляется ДО пагинации и берёт все найденные строки.
- DOM никогда не является источником данных, порядка колонок или состояния.

Если понадобилось прочитать что-то из DOM, чтобы посчитать, — архитектура уже сломана.

# 2. СОСТОЯНИЕ — ПЕРВИЧНО, DOM — ВТОРИЧЕН

Всё живёт в `window.__pvtState[CFG.ns]` (RETRO 2). Минимальный набор ключей —
имена держи ровно такими, чтобы правки разных сессий не расходились:

```js
state.search          // строка поиска
state.sortKey         // ключ колонки
state.sortDir         // 'asc' | 'desc'
state.page            // номер текущей страницы, с 0
state.pageSize        // строк на страницу
state.columnOrder     // массив ключей колонок, ЕДИНЫЙ источник порядка
state.selectedFields  // выбранные пользователем метрики
state.collapsedGroups // свёрнутые группы
state.tip             // текущий тултип
```

Любая новая функция сначала встраивается в состояние и только потом в DOM.
Drag колонки меняет `state.columnOrder`, после чего UI перерисовывается из состояния —
а не наоборот.

# 3. CAPABILITY-МЕТАДАННЫЕ ВМЕСТО УСЛОВИЙ ПО ИМЕНАМ

Когда разные метрики поддерживают разный набор функций, описывай это данными,
а не растущей цепочкой `if (key === 'fact' || key === '...')`:

```js
CFG.metrics = {
  fact:                { hasTrend: true,  sortable: true, locked: false },
  expectedCompletion:  { hasTrend: false, sortable: true, locked: false },
  period:              { hasTrend: false, sortable: true, locked: true  }
};
```

Полезные флаги: `hasTrend`, `sortable`, `copyable`, `searchable`, `draggable`,
`locked`, `defaultVisible`, `format`.

`locked: true` — это системные поля (дата, единица измерения). Они не считаются
пользовательским выбором метрик и их нельзя снять.

# 4. RETRO 27–40

Номера продолжают реестр `PATTERNS.md` и не пересекаются с ним.

| # | Симптом | Причина | Лечение |
|---|---|---|---|
| 27 | Пагинация ломает поиск | поиск выполняется по отрендеренному DOM или по текущей странице | поиск и фильтрация всегда по полной модели; пагинация применяется ПОСЛЕ search/filter/sort |
| 28 | Пагинация ломает копирование | copy читает DOM или `pageRows` | copy/export строится из полного набора отфильтрованных строк, а не из DOM и не из текущей страницы |
| 29 | Пустые значения всплывают наверх при DESC | `null` / `''` / `NaN` участвуют в обычном comparator | пустые значения всегда уходят в конец, независимо от направления сортировки |
| 30 | UI лагает на 1000+ строках | в DOM одновременно все строки и много обработчиков | рендерить только текущую страницу; поиск и сортировку делать над JS-моделью |
| 31 | Тултип уезжает за границу вьюпорта | позиция считается только вправо и вниз от цели | измерить тултип и выбрать сторону; клампинг по `window.innerWidth/innerHeight`. Расширяет RETRO 26 |
| 32 | Sticky-колонка не закрепляется | sticky-ячейка лежит не в том scroll-контейнере либо не имеет `left` / `z-index` / фона | горизонтальный скролл принадлежит таблице; sticky-ячейки получают `position:sticky`, `left`, `z-index` и непрозрачный фон |
| 33 | После правки соседней функции ломается clipboard | экспорт завязан на текущую DOM-разметку | единый `buildExportRows()` из модели + текущий порядок колонок; DOM не источник экспорта |
| 34 | Перестановка колонок расходится с данными | порядок колонок хранится только в DOM | `state.columnOrder` — единый источник для шапки, строк и экспорта |
| 35 | Подсветка поиска ломает вёрстку | highlight делается `replace` по готовой HTML-строке | искать по сырому нормализованному значению; сначала экранировать, потом подсвечивать |
| 36 | Только системные поля считаются выбранными метриками | проверка вида `selected.length > 0` | дата, единица и прочие `locked`-поля не считаются пользовательским выбором |
| 37 | Обязательное поле можно выключить | все поля используют один общий toggle | `locked`-поля нельзя снять: контрол `disabled` или не показывается |
| 38 | Группа и дочерние поля визуально разъезжаются | разные правила `padding`/отступа после сворачивания | категория и потомки используют единую grid/indent-систему |
| 39 | Метрика без динамики показывает пустой блок динамики | UI строится по наличию значения | использовать capability-метаданные (`hasTrend: false`) и не рендерить блок вообще |
| 40 | Скрытие строк не решает проблему производительности | строки всё равно создаются в DOM, просто невидимы | не создавать невидимые строки: сначала срез страницы, потом сборка HTML |

# 5. ОБЯЗАТЕЛЬНЫЙ СМОУК ПОСЛЕ ЛЮБОЙ ПРАВКИ

Большинство регрессий возникало НЕ при разработке функции, а после добавления
соседней. Поэтому после каждой правки таблицы перепроверяй связку целиком:

**поиск → сортировка → пагинация → копирование.**

Сценарии — в `REGRESSION.md`.
