# WORKFLOW — ШАГИ 0, 1, 2 подробно

Читай на ШАГЕ 0/1/2, то есть один раз за проект. На СБОРКЕ и СДАЧЕ этот файл
не нужен: там работают NOTES, шаблон и правила из `SKILL.md`.

## ШАГ 0. Разведка

`ls` папки ДО любых действий. `<скилл>` во всех командах ниже — папка, где лежат
`SKILL.md` и скрипты; определи её один раз и запиши в NOTES §0, в папку проекта
скрипты не копируются (`SKILL.md`, «ГДЕ ЛЕЖАТ СКРИПТЫ»).

Затем `node <скилл>/smoke.mjs --env` — уровень проверки
(`bootstrap.py` на ШАГЕ 1 прогоняет его сам — тогда отдельно не запускай):

- код 0 → скажи пользователю: проверка будет полной, включая браузерную;
- код 2 → в ПЕРВОМ ЖЕ ответе предложи установку командой из вывода `--env`,
  одной строкой. Это не «вопрос по задаче» (правило 8 не про это) и НЕ блокер:
  «нет» или молчание — работа идёт, сдача будет с `B1`–`B5` = `N/A`.
  Явное «да» — установи сам, перепроверь `--env`, продолжай. Без «да» пакеты
  не ставятся. Второй раз не переспрашивай.

Дальше по содержимому папки:

- Макета нет → ШАГ 1.
- Макет и/или SQL есть → прочитай SQL целиком, HTML по правилу 4 → ШАГ 2.
- Папки нет → спроси имя/путь → ШАГ 1.
- Есть `<name>.NOTES.md` с незакрытыми пунктами → возобновление (правило 6).

## ШАГ 1. Болванки — одной командой

    python3 <скилл>/bootstrap.py <папка-проекта> [<имя>]

Создаёт папку и пять пустых файлов из `templates/`, сам гоняет `validate.py
--template`. Шаблоны для этого читать НЕ нужно. Ничего не догадывай: не выдумывай
поля в `CFG.fields`, не заполняй `FIELDS.md`, не придумывай макет и SQL.

Затем СТОП: «болванки готовы, пришли HTML-макет и SQL».

Не запустился — `BLOCKED.md`. Руками болванки собираются ТОЛЬКО после явного
«делай вручную», и порядок там же.

## ШАГ 2. Перенос макета в JS

0. `python3 <скилл>/scan-layout.py <name>.html` — M, план чтения, содержимое
   повторов и ЧЕРНОВИК `CFG.order`. Черновик забери целиком: это и порядок
   категорий для `buildModel` (правило 14), и значения для автомока `smoke.mjs`
   (правило 11). Ключи — имена колонок SQL, их подставляешь ты.
1. Покрой HTML по правилу 4 и плану сканера → NOTES §1 (реестр элементов
   и mock-значения) и §2 (покрытие). В контексте держи NOTES, не HTML.
   Порядок категорий из census'а перенеси в §1 КАК ЕСТЬ — он часть ТЗ (правило 14).
2. Прочитай SQL → NOTES §3: выходные колонки и типы. Их же в `CFG.fields`.
3. Сопоставь реестр с колонками. Нехватка → вопрос (КОНТРАКТ, п. 3),
   решение → NOTES §4.

**Здесь ПЕРЕДАЧА** (`SKILL.md`, раздел «ПЕРЕДАЧА»): реестр снят, макет больше
не нужен, сборку лучше вести с новой сессии. Дальше — шаги 4–10, по правилу 5:
блок → чекпоинт → блок.

4. Перенеси CSS в `buildCSS()`, префиксовав КАЖДЫЙ селектор через `CFG.ns`;
   цвета, шрифты, отступы — в `CFG`. Рамку демо-страницы макета (фон и отступы
   `body`, центрирование, фикс-ширину внешнего контейнера, оконные `@media`)
   НЕ переноси: корень остаётся резиновым (RETRO 48, 49). Как именно — `RECIPES.md`.
5. Перенеси разметку в `buildHTML()` конкатенацией, данные через `esc()`.
6. Напиши `buildModel()` под фактические поля: здесь считается ВСЁ производное.
   Обработчики навесь ОДИН РАЗ СНАРУЖИ `render()`.
7. Заполни `FIELDS.md`: точные имена, типы, чек-лист ручных настроек Proteus.
8. `python3 <скилл>/check.py <name>.chart.js` — обе проверки одной командой,
   почини все FAIL. Проверки разные: первая смотрит на код, вторая на экран,
   и зелёная первая при красной второй означает ровно одно — график
   не работает. По очереди их гонять не надо: правка под одну ломает другую,
   и сессия уходит на круги (RETRO 66). `check.py` ведёт журнал прогонов
   и сам скажет, если код был починен и упал снова, — тогда стоп
   и ОСПАРИВАНИЕ (`SKILL.md`), а не следующий круг.
9. Проверь шапку `данные:` в выводе smoke. Строка «вслепую: N колонок вне
   CFG.order» означает, что автомок заполнил их наугад и часть виджета вышла
   нулевой: жёлтые строки про тултипы и SVG после этого — про мок, а не про
   виджет. Заполни `CFG.order` (черновик даёт `scan-layout.py`) и перепрогони.
10. Прогони `SELF_CHECK.md` и заполни его — по пунктам скилла, своих разделов
    не сочиняй. Затем `check.py` ЕЩЁ РАЗ: `Z5`/`Z6`/`Z6b`/`F1` смотрят
    на NOTES, `FIELDS.md` и отчёт, и до их появления «всё зелено» ничего
    не значит. Без полного PASS НЕ СДАНО.
